# CS-255

1. The DriverPass project focused on designing a web-based system to improve driver education and business operations. The client was DriverPass, a driver training company, with Liam (the owner) serving as the primary stakeholder. They wanted a comprehensive system that allows customers to access online learning materials, take practice DMV tests, and schedule driving lessons, while also enabling staff to manage customers, instructors, vehicles, and appointments in a centralized platform.

2. I did particularly well in identifying and organizing both functional and nonfunctional requirements. My design clearly outlines what the system must do—such as scheduling lessons, managing accounts, and tracking progress—while also addressing performance, security, and usability. Additionally, I effectively incorporated security measures like encrypted connections, role-based access, and account protection, which strengthens the overall system design.

3. I would revise my UML diagrams, especially the activity and sequence diagrams. While they capture the general process, they could be improved by making the workflows more detailed and visually clearer. I would refine the flow of actions, ensure consistent labeling, and better represent decision points so that the diagrams more accurately reflect real-world user interactions and system processes.


4. I interpreted the user’s needs by analyzing the client’s goals, such as improving DMV test preparation and simplifying scheduling. I translated these needs into system features like online courses, practice tests, and appointment management. These were then implemented as functional requirements and supported by system components like a web interface and database.

Considering user needs is critical because the system must solve real problems for both customers and staff. If the design does not align with user expectations, the system may be inefficient, difficult to use, or fail to meet business goals.


5. I approach software design by first gathering and analyzing requirements, then breaking the system into components and defining its functionality. I use UML diagrams to visualize system behavior and structure before deciding on technical implementation.

In the future, I would continue using techniques such as requirements analysis, use case modeling, and iterative design. I would also focus more on user feedback, prototyping, and refining diagrams early to ensure the system is both functional and user-friendly before development begins.
